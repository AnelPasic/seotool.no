# Content Voice — editorial instructions for an exported Astro site

These instructions ship **inside the standalone site**. Use its own files; no upstream installation manifest or vendor directory is required.

Before writing or editing **any customer-facing text** (Hero, services, articles, glossary, FAQ, CTA supporting copy):

1. Read **fresh** `coordination/CONTENT-TONE.json` (the only saved preset choices), `coordination/CONTENT-VOICE-PROFILE.md` (brand interpretation), the site `AGENTS.md`, and the current content/approved customer facts. Apply a project-specific copy-style guide if one exists. Never infer today's selections from an old chat, an unrelated client or a template.
2. Resolve `heroPreset`, `servicePreset`, `explanationPreset` or `faqPreset` for the requested content role; `inherit` uses `defaultPreset`. `editorNotes` are lower-priority guidance. A CMS change affects **future writing only**; it neither rewrites existing pages nor runs an AI service.
3. Apply the editorial quality check **before saving**: Does the intended buyer immediately understand the answer, the real-world consequence and next step? Is it specific rather than interchangeable agency language? Are SEO/search intent, conversion purpose, facts, evidence, claims, repetition and neighboring text handled correctly? More detailed project-specific approved quality guidelines apply if actually available; this exported site does not depend on documents outside its root.
4. **Commercial Value Gate for any sales-intent Hero, service, package, offer or lead CTA:** sell the desired business outcome, not a list of easy DIY tasks. Check believable competence/proof and implementation, realistic time, what work the provider owns vs the buyer, and why the buyer should hire this provider rather than do it alone; give an approved next step. If text merely says 'we update Google profile details' and invites 'I'll do that myself', rewrite. An article/how-to should still answer the question instead of forcing a pitch. This is an editorial test, not automatic validation or permission to invent guarantees/offer terms. Apply it **before** the chosen tone - even Hysterisk must sell an actual service when used on a sales page.
5. **Humor and memorability are deliberate, not optional decoration.** `spiss` means a sharp observation; `spissplus` means a concrete insight with more edge. **`spisspluskomisk` must be recognizably funny** when the subject allows it: use an unexpected everyday contrast, dry absurdity or a short punchline. **`spisspluskomiskplus` goes one deliberate step further:** a distinctly comic, original and vividly absurd *but still recognizable* analogy followed by a punchline grounded in the buyer's real problem. It should earn a real smile, not just applause for clever wording. Escalate originality rather than joke count; if the subject does not support it, write plainly. **`spissplushysterisk` is not just 'a bit more cheeky':** use an original comedic premise, escalation and real left-turn/punchline, or similarly strong character dialogue/callback. Internally try distinct comedic premises before selecting; if the copy only elicits a polite smile or repeats a tired analogy, reject it as level 7 rather than renaming it 'hysterical'. Humor can lead on a deliberately comic brief; don't impose 'useful answer first, joke last' on this level. For a saved level-7 Hero selection, retain a standalone understandable service/value H1 but deliver the actual comedy through H1 and/or supporting copy, not a watered-down one-liner. Level 7 is opt-in for SoMe, campaigns **and owner-approved customer websites**, never a universal default. Aim jokes at agency clichés and absurd systems, not customers. No borrowed standup, canned celebrity jokes, invented performance claims or spurious promises. For levels 3-6, give the useful answer first where appropriate and keep humor sparse; for `balansert`, clarity leads. For all levels, sensitive copy remains nøktern.
6. **Keep sensitive/transactional facts nøkterne**, regardless of the selected preset: prices, contracts, proof/results, legal/privacy, health, safety, accessibility, forms, checkout and errors. This applies to factual sentences even inside an otherwise Spiss+ section. Do not invent customers, numbers, search rankings, savings, or promises.
7. For a requested content revision, compare the existing text with the proposed version for **clarity, useful memorability, accuracy and project voice**. Preserve approved prices, proof, page structure, anchors, IDs, SEO intent and recent OWNER/CMS edits. A tone selector change alone never authorizes rewriting. Edit only the requested source fields.
8. After a scoped edit, verify the exact Git diff/readback. Report source verification separately from real authenticated Pages CMS save, Cloudflare build, deployed preview and launch. None of those runtime steps is implied by a successful local test.

This is a reusable, **brand-neutral** writing process, not permission to import Medon's humor or Optimalisering Oslo's phrasing into another customer's site.
